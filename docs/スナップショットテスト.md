# スナップショットテストの運用ガイド

スナップショットテストは、実行結果を保存済みの期待値と比較し、変更を検出するテストです。
テストが失敗した場合は、期待値を更新する前に差分の原因を確認してください。

## このリポジトリのスナップショット

- 単体テストでは、Vitest のスナップショットで設定やプロジェクトデータなどの出力を比較しています。
  期待値はテストファイル内や、その近くの`__snapshots__`ディレクトリに保存されています。
- ブラウザ End to End テストと Storybook の VRT（Visual Regression Testing）では、Playwright でスクリーンショットを比較しています。
  ブラウザ End to End テストには、音声ファイルを比較するテストもあります。

## テストが失敗したときの確認

1. テスト名と失敗メッセージから、変更された出力を確認します。
   画像の場合は、Playwright のレポートにある期待画像・実際の画像・差分画像を比較します。
2. その差分が、今回の変更で意図した結果かを確認します。
   例えば、UI の変更で意図した部品だけが変わっているか、データ形式の変更で必要な項目が保持されているかを確認します。
3. 意図しない差分の場合は、実装やテストの実行条件を調べます。
   同じ条件で再実行すると結果が変わる場合は、日時や乱数、非同期処理の待機などに依存していないか確認します。

画像には OS やフォントなどの実行環境による差が出ることがあります。
現在のスクリーンショットテストは Windows を対象としているため、更新時は対象の環境を確認してください。
差が小さいことだけを理由に期待値を更新せず、意図した変更か判断できない場合は PR で相談してください。

## 期待値を更新する場合

仕様変更や UI の変更によって出力が意図どおり変わった場合や、新しいテストの期待値を作成する場合に更新します。
テストを通すことだけを目的として更新しないでください。

### 単体テスト

対象のテストファイルを指定すると、更新範囲を絞れます。

```bash
pnpm run test:unit tests/unit/domain/project.spec.ts --update
```

上記はプロジェクトデータのテストを指定する例です。変更対象のテストファイルに置き換えてください。
更新後は同じテストを`--update`なしで実行し、期待値と一致することを確認します。

### スクリーンショット

GitHub Actions とローカルでの具体的な更新方法は、[README のスクリーンショットの更新](../README.md#スクリーンショットの更新)を参照してください。
Storybook のスクリーンショットをローカルで更新する場合は、次のコマンドを使います。

```bash
pnpm run test:storybook-vrt --update-snapshots
```

Storybook のテストでは、更新時に削除済みの Story に対応するスクリーンショットも削除されます。
削除された画像についても、対応する Story の削除に伴うものか確認してください。
更新後は`--update-snapshots`なしで対象のテストを実行します。

## PR とレビューで確認すること

- 実装の変更と期待値の変更を一緒に示し、期待値を更新した理由を PR に記載します。
- 変更した出力だけでなく、無関係なスナップショットの更新や削除が混ざっていないか確認します。
- 画像の差分は、配置・文字の欠け・意図しない非表示なども確認します。
- データの差分は、必要な項目が失われていないか確認します。
- 実行したテストと、画像の場合は更新した OS を記載します。

## スナップショット以外の検証を検討する場合

出力全体よりも特定の振る舞いが重要な場合は、その値や操作結果を直接検証する方が意図を読み取りやすくなります。
例えば、大きなデータ全体を保存する代わりに必要な項目を比較したり、日時や乱数に依存する部分の条件を固定したりする方法があります。
スナップショットの差分を確認しても何が正しいか判断しにくい場合は、検証する範囲を見直してください。
